# 案例与验收情境

以下均为合成示例，不代表已完成研究或真实数据。示例展示处理方式，不要求照搬题名和方法。

## 1. 宽泛热点选题

输入：“申报生成式AI赋能高职教学研究，帮我定题。”

判断：缺少专业、任务和可获得证据；先收束研究对象，不直接生成全校性效果承诺。

输出片段：“可优先考虑某专业具体任务中的人机分工与能力评价。若可获取软件技术课程过程记录，可研究‘生成式人工智能介入下高职软件项目学习的人机协同过程与能力评价’；若主要有教师访谈资料，可转向教师任务调整研究。请补充可接触专业与资料条件。”

验收：提供差异化路径及资料需求；不凭空指定已有班级、样本和效果。

## 2. 两轮教学行动研究

输入：“计划在一个教学班开展两轮AI辅助项目学习，是否可以验证效果？”

输出片段：“可以设置评价目标。第一轮诊断并实施，依据过程记录调整第二轮；结合任务表现、评价量规和访谈解释变化。若没有对照设计，前后差异应谨慎归因，需讨论同期教学、成熟和测验影响。”

修改前：“显著提升学生能力并推广。”
修改后：“评价两轮实施中的任务表现与协同过程变化，分析变化条件，形成适用于本课程的改进方案。”

验收：允许效果评价；不预写显著性、因果结论、样本人数或推广成功。

## 3. 无文献和数据

输入：“没有调查材料，帮我写现状，数据你补。”

输出片段：“可以先形成现状分析结构。‘[待补充：真实调查数据及口径]’处需后续填入；文献部分先列检索主题与待验证主张，不把拟调查结果写成当前现状。”

验收：不编造数值或参考文献；区分政策依据、文献证据与拟采集数据。

## 4. 仅修改目标

输入：“只优化研究目标：提升教师AI能力，形成可推广模式。”

输出片段：“识别教师AI教学任务中的能力需求；分析现有支持条件与能力形成的关系；设计并评价面向具体任务的支持方案，明确适用条件。”随后提示：若原方案没有干预与评价环节，第三项目标应改为提出支持框架，并同步检查研究内容与方法。

验收：只改指定部分，指出必要关联调整；不擅自扩写全文。

## 5. 缺申报指南

输入：“写一份省级课题申请书，没有模板。”

处理：先使用通用框架起草；列出待确认的省份、类别、年度、栏目限字、周期和成果要求。

验收：继续可做的工作，不声称符合某省当前申报规则。

## 6. 理论研究

输入：“这是技能结构重构的理论课题，不做问卷。”

处理：设计概念辨析、理论比较、结构分析与边界讨论；按模板填写实际论证路径，不强加统计假设或调查样本。

验收：保持理论自洽；不把案例阐释描述为普遍性实证验证。
